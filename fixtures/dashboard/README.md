# Dashboard presentation records

Generated from MAIN with the built `eplyx` binary and projected by
`scripts/dashboard-fixture.mjs`. The 66 analytical files (496,193 bytes)
retain their exact generated bytes. `provenance.json` lists every size and SHA-256.
They contain nine runs across four local projects, with saved counterexamples and
reproductions. Candidate binaries and raw state captures are omitted, so these
records cannot be replayed and never substitute for the frozen T0 contract.

The transition-acceptance project scales the minimal synthetic population down
by one million for readable display quantities. Healthy reference runs have
20/20 stress cases behaving as specified. Deficient-reserve deadline-defect runs
have 19/20, an observed eligible-holder failure and a derived deadline finding.
The token-migration project retains the original minimal quantities and its
reference/deadline-defect comparison. A second recipe generates distinct public
addresses. The analytical project records a hypothetical lifecycle declaration
and a synthetic current observation with all five paths untested. None claims
current mainnet qualification or an official issuer transition.

`view-models.json` is a derived rendering input exported by
`engine/examples/dashboard_views.rs`. Its separate provenance record distinguishes
it from the exact analytical files. `ids.json` and `ids.rs` identify the saved
presentation runs; timestamp and engine-binary metadata describe the build that
generated them, not every later build that renders them.

To generate a new independent fixture directory, first build the engine and the
`dashboard_records` example, then run:

```sh
node scripts/generate-dashboard-fixtures.mjs <new-output-directory>
```

The generator refuses an existing destination and executes children with an
empty environment. It does not rewrite these fixtures or any historical record.
The synthetic provider lives in the example and makes no network request. The
full generator and its projection are checked during T8; individual engine
outcomes remain covered by the T0 reference and migration suites.
