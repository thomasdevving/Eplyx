## State, identity and minimal future evidence contract

Within each version pair, message/metas, non-pool accounts, dependency bytes/loaders, Clock/runtime, signer assumptions and watch set must be identical; only that version's verified post-config pool differs. Between versions, only target code is explicitly substituted. Schema-1 VM loading creates the program's loader/cache representation per VM; the candidate is not written into a historical loader account or saved as an installed world. No additional historical input account, dependency, balance or Clock refresh was required by the probe. A candidate needing new layout, dependencies, state or handoff must return an explicit unsupported boundary.

Keep proposal identities separate: probe upgrade ID `f563005c631c121c937e3f7b30b3a24f9bfd69b6b9158c0dfd0345beb8cea751`; parameter ID `60a78b2069fd1232d6b258ed27bcd503c17a92e1da52c71dd3b82a250905b9f7`. Neither replaces the other.

Propose `analysis_input_id = canonical_digest(("eplyx-upgrade-parameter-interaction-input-v1", body))`. The versioned body binds both ChangeSpec IDs; immutable record/bundle/S0 account commitments; V1/V2 ELF hash/length/program/loader; exact dependencies/runtime/Clock; exact SetFee and full user-action messages; manager/payer envelopes, signer and possession assumptions; candidate qualification receipt/interpretation revision; and the explicit four-cell/fresh-VM/pool-only-handoff semantics plus measurable quantity definitions. Altering candidate, proposed fee or record changes this identity. Cells are combinations, not an ordered list of on-chain changes. Labels and file locations are not identifying.

Minimal report: immutable historical source and separate executable overlay; each cell's pre-account/message/program commitments; both config executions with pre/post snapshots, logs/CU/fees and manager assumptions; both verified pool states or explicit unavailable/rejected status; four action outcomes with watched post-accounts, independent reconciliation/rollback and limitations; exact individual effects/contrasts only for executed, reconciled, semantically comparable cells. Preserve config rejection, action rejection, reconciliation mismatch, unsupported interpretation and execution unavailability distinctly. The analyzer must never manufacture zero for a missing cell. Offline verification must bind these cross-object relationships and reproduce the actual VM evidence, not merely accept a resealed JSON hash.
