# Phase U3 — modern replay surface: preflight evidence

**Status: incomplete preflight, stopped before replay-engine changes.** The
original U2 census was recovered, but its complete transaction sample was not
preserved. Only two of the 18 supported observations have recoverable identities
and RPC captures. An exact BEFORE/AFTER experiment cannot yet be conducted.
This is not a completed U3 phase or a claim that Kamino production replay works.

The source census script explains the missing evidence: it increments an
aggregate counter for each observed action, but appends a transaction's signature
and slot to `detail` **only when `n_loaded == 0`**. It does not save fetched
transaction messages, the 1,000-signature source listing, failed-fetch membership,
or identities of LUT-backed observations. The recovered `sigs.json` contains
100 signatures from slots 448163393–448164098, an earlier sample; it cannot be
used as the missing source listing for this census.

The census field named `eligible` counts **LUT-free instructions**, not engine
admission or baseline-validated replay eligibility. In particular, its two
deposit entries are not production replay proof. The 0/0 eligibility figures
above are the U2 report's conclusion, not a reproduced aggregate engine run.

There is another provenance defect: the artifact reports `examined: 200`, while
`with_klend_top_level: 110` plus `no_klend_top_level: 89` describes 199 classified
transactions. The script writes its periodic snapshot after incrementing
`examined` and **before classifying that transaction**. Session history records
that the process was stopped and this progress snapshot copied to `census-final`.
The aggregate artifact is authentic U2 evidence, but not a complete capture.

No new activity window was scanned and no replacement sample was substituted.
Matching aggregate counts in another scan would not recover the original
fetch-success membership.

## No-LUT lifecycle diagnosis

Detailed amounts and account identities are retained in
[`lifecycle-diagnosis.json`](examples/phase-u3-before/lifecycle-diagnosis.json).
Both transactions execute the legacy SPL Token program
`TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA`, and wrap the native mint
`So11111111111111111111111111111111111111112`.

**Slot 448170827: existing ATA, then closure.** The validator records a zero
token amount and 1,488,440 lamports before execution for
`BshUsSancK4CKL7yt9Nmtgy1saPQekwNthZ8HmCo7jR9`. The ATA instruction has no
creation CPIs. System funding is 1,690,100 lamports, and the KLend deposit's
TransferChecked transfers 201,660. CloseAccount names the wallet/payer
`Gruh6YKhDtH3yreu2G725ySoBfhNH6DBAtAaSDCt5aBr` as destination and signing
authority; the account's post-balance is zero and it has no post-token entry.
Balance conservation implies a close refund of 2,976,880 lamports.

**Slot 448170087: ATA creation, then closure in the same transaction.**
`Bbr3Y7Wcy4xs5RqrGw2ZWkPQqjLZqwmNxQdwAEjt7Cdc` starts at zero lamports and has
no pre-token entry. The first CreateIdempotent invokes System CreateAccount with
1,488,440 lamports, 165 data bytes and the SPL Token owner, followed by token
initialization. A second CreateIdempotent has no creation CPI. System funding
then contributes 1,001,488,440 lamports, and KLend transfers 1,000,000,000.
CloseAccount names wallet/payer `3boJzRQsSSiP11GKrk4QiDW21uTXmT3S2h5eHXsNvjgj`
as destination and signing authority. The account ends at zero lamports with no
post-token entry. Balance conservation again implies a 2,976,880-lamport refund.

Therefore **actual account creation is required for the second deposit**.
This path includes a transient account absent at both transaction boundaries;
boundary absence must not hide its creation and closure during execution.

The inferred refunds include residual funded native value, so they must not be
labelled wholly as rent recovery or as Kamino proceeds. Historical account bytes
and intermediate native-reserve fields have not been acquired. These are
transaction-metadata observations and conservation calculations, not baseline
fidelity proof. The official [SPL Token processor](https://docs.rs/spl-token/latest/src/spl_token/processor.rs.html)
reconciles SyncNative against the account's native reserve and permits native
account closure with residual native value; the [ATA processor](https://github.com/solana-program/associated-token-account/blob/main/program/src/processor.rs)
returns early for a valid existing idempotent target. These sources clarify the
diagnosis; they do not establish equivalence with the historically deployed ELF.

An admission error is not proof that LiteSVM needs an emulator. Any continuation
must execute the real historical dependencies and derive evidence through U1.

## LUT research before implementation

The pinned dependency graph already contains official
`solana-address-lookup-table-interface` 3.1.0. Its `AddressLookupTable` and
`LookupTableMeta` supply a decoder and slot-aware lookup operations; there is no
justification yet for a custom account-layout parser. The installed crate source
was inspected directly.

Its warmup rule exposes the entire address array only when execution slot is
greater than `last_extended_slot`; otherwise the usable prefix ends at
`last_extended_slot_start_index`. Deactivation eligibility depends on the
execution bank's SlotHashes context. A historical table snapshot's query slot
and the slot passed to lookup are distinct. S-1 has **not** been adopted as a
complete LUT proof model; same-slot extensions, deactivation, boundary evidence,
metadata cross-checking and exact message identity still need investigation
against the recovered original LUT observations before implementation.

## What remains necessary

The original 18 supported transaction identities are needed, with the original
capture membership, preferably all 200 captured RPC responses. Given exact
identities, immutable historical transactions can be reacquired without selecting
a friendlier window; original LUT messages and loaded metadata must then be
preserved. A complete immutable BEFORE table must precede replay-engine changes.

No LUT/lifecycle support or record-schema migration was implemented. No Kamino
production record or corpus was created, no newly eligible signature is claimed,
and no AFTER counts, mutation results or production storage overhead are available.
An A/B/C phase conclusion is pending because the experiment has not been run.
Adapter #4 must not start while this replay-surface validation is incomplete.
