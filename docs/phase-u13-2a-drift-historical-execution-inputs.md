# Phase U13.2A — Drift historical execution inputs

## Result: U13.2A-C, historical feature-set runtime gap

The exact historical Drift ELF is available. U13.1 had already retained the complete parent-slot ProgramData in seven exact-slot Alchemy Account Archive slices; this phase independently reassembled those frozen slices, verified their raw response and content hashes, and retained the derived [ELF](examples/phase-u13-2a-runtime/historical-drift.so). The ELF is **6,673,069 bytes**, SHA-256 `56bb3c1218ca4cc1158116c008439a48ca942f7e2898227494ce2769a7fdce5d`. The complete ProgramData account is **6,673,114 bytes**, SHA-256 `ca89b99a4ce9cd09a35e7fd881b09099397543a9a1122e93f9a68b1349007728`. These are provider-observed historical account bytes, not source-to-ELF build provenance or a validator attestation.

The current generic `LiteSvmBackend` cannot represent the target slot's feature set. Exact-slot feature-account acquisition finds 275 active features among the 311 identities inventoried by U9 at a later slot. Another 34 activated after slot `409942000`; 32 were absent at the target and two existed but were inactive. The frozen LiteSVM 0.16.0 mainnet feature list itself includes **26 post-target activations**. `LiteSVM::new()` loads that later mainnet set; Eplyx's `RuntimeProfile::validate` accepts only the fixed `LiteSVM 0.16.0 mainnet` profile, and `LiteSvmBackend` has no historical `with_feature_set` input. This is a generic historical feature-set configuration gap. Running the target now would test a different runtime. No baseline execution, output comparison, replay observation, corpus, bundle, or Drift semantic conclusion was made. The U13 SpotMarket transaction-boundary blocker remains separate and unchanged.

## Execution decision and proof boundary

The historical binary, direct account seeds, generic program census, Clock, Rent, EpochSchedule, normal-blockhash model, and fee arithmetic are ready for a later feasibility attempt. The exact historical feature set cannot be injected through the current `RuntimeProfile` and `LiteSvmBackend`; exact native behavior and the materiality of unavailable per-slot sysvars are also unresolved. This meets **U13.2A-C — runtime gap** rather than U13.2A-A. The missing generic capability is a content-bound historical feature set and compatible native/runtime selection, with a materiality gate for unavailable sysvars. No Drift-specific branch or workaround was introduced.

Because there was no historically configured execution, validator success, fee, 97,801 CU, logs, and raw outputs have **no local comparison**. U13's User and PerpMarket block-final bytes remain safe future checks because no other block transaction writes them. The block-final quote SpotMarket bytes remain only a terminal checkpoint after four later successful writers; no tx-73 SpotMarket post-state was derived or validated here. No observation or product proof may be built from this input audit.

The next generic step is to add a historically bound feature-set input to `RuntimeProfile` and `LiteSvmBackend`, qualify native/loader behavior for this slot, and test SlotHashes/other unavailable-sysvar materiality. Only then run the smallest target-only feasibility execution using this ELF and the frozen parent seeds, compare User and PerpMarket and validator envelope, and keep SpotMarket explicitly unverified pending the U13.1 causal closure. Source-to-ELF provenance remains a separate question. Existing U13, U13.1, and F1 artifacts were not overwritten.
