**Decision C: events available, but completeness unproven.** Authenticated Alchemy Account Archive and Yellowstone historical replay both serve the frozen Orca slot `448760958`. The finalized stream matches the frozen block and its 1,131 ordered signatures. The historical account stream, however, exposes only the last update for each address in the slot. A fee payer with 18 proven fee deductions has one returned account event, attributed to the eighteenth transaction. The stream therefore cannot certify an intra-slot write timeline or a generic transaction boundary. No schema-2 Orca observation, replay, fidelity result, corpus, bundle, or semantic result was created.

## 3. Block, fork, transaction, and account-event identity

The unfiltered raw [protobuf stream](examples/phase-u7-full-slot/stream.pbseq) contains 2,464 account events, 1,131 transaction events, one block-metadata event, and one finalized-slot event for S. All **1,131** `(index, signature)` pairs match the frozen validator block with no missing, extra, duplicate, or mismatched indexes, as recorded in the [offline analysis](examples/phase-u7-full-slot/analysis.json). The block hash is `GoYyJFwVcoT4UWnZCDtPTG4u82bWJahxmNMYAPoVjHqi`; parent slot is `448760957`; the metadata declares 1,131 executed transactions. Target index 259 and the first later writable-overlap transaction at index 385 match the U5 evidence. The slot status is `SLOT_FINALIZED`. The historical protobuf account and transaction messages have no `bank_id`; finalization plus matching block hash, parent, and complete signature list identifies the canonical block, but individual account events carry only slot and transaction signature, not an explicit bank hash. No bank identifier was invented.

Account updates carry pubkey, slot, `write_version`, optional `txn_signature`, lamports, owner, executable, rent epoch, full data, and retained raw event SHA-256. Of the 2,464 S events, **2,459** have a transaction signature that maps into the matched block; **five** lack one (runtime/sysvar-style updates, including RecentBlockhashes). For every transaction-attributed S event, observed `write_version = 1000 + transaction_index`; all 12 returned target-key updates carry `1259`. Multiple distinct accounts share a version. This is the **observed historical provider encoding**, not Agave's original globally allocated per-account write version. The [filtered and unfiltered comparison](examples/phase-u7-full-slot/filter-comparison.json) shows identical account payloads for the 22 target keys, so the filtered request did not hide additional updates that the unfiltered replay returned.

The decisive [same-account witness](examples/phase-u7-full-slot/coalescing-witness.json) is fee payer `FVnv5qH7dsrBzEDwJ8dN2m9PFtKTBAQFtqWF3M9LpwMg`: the validator block records **18** transactions with 18 distinct pre/post lamport changes, including fee deductions at indexes 258 through 933. The unfiltered historical account stream contains **one** event for this address, attributed to index 933, with the final validator balance. Across all 2,464 account events, there are 2,464 distinct addresses and zero repeated-address events. Thus the endpoint coalesces at least this proven multi-write account to its terminal slot state. Transaction events remain complete; their completeness does not restore the omitted account versions. The archive cursor also returns only this terminal balance.

## 4. Boundary attempt and reconciliation

The [temporary 22-key timelines](examples/phase-u7-archive/target-timelines.json) retain separate S-1 and S archive response hashes, complete state summaries, raw stream-event hashes, transaction attribution, and explicit `completeness = unproven_coalesced_historical_account_stream`. Eleven present target-key account events match independent S account content on **presence, owner, lamports, executable, rent epoch, and every data byte**. One zero-lamport, zero-data target event is a deletion-shaped tombstone and both archive checkpoints report that address absent; it is not treated as a normal present account. Nine other keys have no stream update. The RecentBlockhashes key has a signature-free runtime event but `null` Archive values at both slots, so its ordinary account timeline cannot be reconciled here. The 22 keys are a screening keyset, not a declared CompleteExecutionV2 watched-account census.

U5's conservative message-key screen found zero earlier writable overlaps, which still makes S-1 a *candidate* pre-boundary for the target. The historical stream cannot independently prove absence of earlier transient writes because it coalesces account updates. The 12 target-attributed events offer candidate post-values, and 11 present values match S, but their being the final target writes is not certified by this endpoint's event-completeness behavior. The target pre-state and post-state are therefore **not admitted** as transaction-boundary evidence.

The eight later writable overlaps remain indexes `385, 819, 846, 857, 860, 861, 896, 1114`. Six involving Whirlpool, vault, tick-array, or oracle roles failed in the validator metadata; 819 and 846 succeeded but overlap only another required key. No later target-role account event was returned. The target Whirlpool stream data equals S Archive data, so this sample does **not** demonstrate a target-post-versus-slot-end byte difference. A writable flag was a conservative possible-write screen, not proof of a committed write. Because coalescing is demonstrated elsewhere in this same slot, lack of a later returned account event is not itself a complete later-write-chain proof. No `UnattributableIntraSlotWrite` was inferred for an ordinary target update; the operative failure is **incomplete account-write history**.

## 5. Decision and follow-up

**U7-C — events available but completeness unproven.** Required facts achieved: authenticated retention, exact S-1/S archive contexts, finalized block identity, complete transaction-index map, full bytes in returned account events, transaction signatures for the target events, and 11 exact terminal-content matches. Required fact failed: a gap-free, non-coalesced list of all same-account writes. The fee-payer witness is a concrete counterexample. The historical stream cannot prove deterministic intra-slot write ordering, target-visible final account state in a contended address, or terminal reconciliation of a complete write chain. The absence of `bank_id` and the signature-free runtime event are additional provenance limits. No Orca replay or `NoSemanticCoverage` result was reached.

The old slot was available, so no replacement sampling policy, new sample fingerprint, new hard candidate, or recent-case result exists. As the single second-provider research path, [Solana Vibe Station Rewind](https://solanavibestation.com/rewind) advertises per-write `getAccountChanges` with transaction signatures and signature-anchored before/after account reads. It is **unqualified**: no SVS credential or authenticated per-write response was available. A guessed anonymous public `/rewind` URL returned HTTP 404 in the [probe receipt](examples/phase-u7-freeze/second-provider.json); that response does not establish product availability or retention.

The real responses justify an **evidence requirement**, not a product schema: a future source must supply all account versions with full content and presence, address, slot, raw event identity, transaction signature and canonical index, unambiguous order for repeated writes, finalized block/fork binding, gap/coalescing proof, and independent S-1/S checkpoints with terminal reconciliation. `write_version` must be interpreted according to the qualified provider contract; the observed `1000 + index` must not be presented as an original Agave write counter. No `AccountObservation`, `ReplayObservation`, bundle CAS, resolver, fidelity, or adapter change is justified now. CompleteExecutionV2 remains unchanged.

The [U7 artifact manifest](examples/phase-u7-freeze/final-manifest.json) lists 94 new files and approximately 18.8 MB of retained bytes, including the raw protobuf stream and 44 archive account bodies; it excludes itself. Analysis was offline once acquisition finished. The credential-value scan found zero hits in U7 artifacts, and the temporary key file was removed.

For prospective collection, Eplyx should retain finalized transaction, block, and **uncoalesced** account-write events, raw payloads, transaction attribution, write ordering, bank/fork identity when supplied, gap detection, and periodic independent checkpoints. This is a recommendation, not an ingestion service implementation. The exact next Astra task is to obtain authenticated **per-write** history for the same frozen slot from one source such as Rewind, first reproduce all 18 fee-payer versions, then verify the 22 target keys against S-1/S checkpoints and the finalized block. Only a successful completeness and boundary proof should trigger a minimal generic schema specification. If that source cannot serve S, prospectively capture a freshly frozen hard same-slot case under the U7 sampling rules. The retrospective Alchemy account stream must remain rejected for transaction-boundary admission.
