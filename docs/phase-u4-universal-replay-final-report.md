# Universal replay architecture — phase U4 report

Status: **bounded product-path success, ready for an adversarial fourth protocol**. The new evidence and replay model works for the two retained Kamino production transactions, while existing Stake Pool bundles remain on their exact V1 wire format. This is not a claim that every Solana runtime feature or historical provider is supported.

1. **HEAD and worktree.** Initial and final HEAD: `84ba410287a4a7ed315a7d779dbaad625fe3bf39` on `main`. The initial freeze in [`phase-u4-freeze/initial.json`](examples/phase-u4-freeze/initial.json) records 615 pre-existing uncommitted status entries and their hashes; all 615 hashes were rechecked unchanged. U4 source, tests, records and bundles are uncommitted; seven tracked source/test files changed. No old bundle or U3F golden was rewritten.
2. **Before.** `ReplayRecord` carried inline state and a legacy-oriented message; `CorpusStore`, bundle and `ci::check` accepted only V1 records. `executor::execute_in_environment` submitted legacy transactions and fidelity checked a narrower result. The code-level map is in [`universal-replay-architecture.md`](universal-replay-architecture.md).
3. **Universal model.** `ReplayObservationV2` is an immutable manifest pointing to historical evidence; `ExecutionInput`, `RuntimeContext`, `ExpectedHistoricalOutcome` and `SemanticTarget` are separate. V1 is read with its old schema and adapted to the common execution backend.
4. **Types/modules.** New `engine/src/universal/{model,evidence,resolver,execution,fidelity,pipeline,bundle}.rs`; `CorpusStore` and ordinary CLI commands gained schema-2 support. The provider-specific local converter is outside replay core.
5. **ExecutionInput.** Tagged Legacy, V0 and an explicit V1 legacy-flattening compatibility variant. Native v0 stores compiled message plus frozen transaction, LUT observation refs and claimed proof. Resolution rebuilds loaded keys from actual LUT bytes; V2 rejects the compatibility variant.
6. **Backend boundary.** `ExecutionBackend::execute(ExecutionRequest)` returns presence-preserving `ExecutionEvidence`. `LiteSvmBackend` submits native legacy or v0 messages through one API. Diagnostics can time runtime setup, program registration, seeding, execution and evidence collection without putting time in evidence identity.
7. **Evidence store.** Bundle-local SHA-256 CAS, with references checked on every read. No global service, RPC, garbage collection or cloud storage was added.
8. **Account content vs observation.** `AccountContent` owns full owner/lamports/executable/rent-epoch/data state. `AccountObservation` binds address, requested boundary/slot, returned context, provider provenance, raw response hash and shared content. Chunked ProgramData observations bind every slice to exact-slot request receipts and reassemble full bytes.
9. **Binary evidence.** Target and dependency ELF bytes are hash-addressed. Resolver checks program header, loader, ProgramData address, deployment slot, authority and full ELF against historical accounts and the dependency manifest. Both observations use the retained target ELF SHA-256 `9db16dd4b7bbfe4f13df850bf880bfc4522fcece06717c0626d625746a3cc85b`.
10. **LUT evidence.** A LUT account observation is separate from the transaction-specific lookup-index proof. The U3B proof is rerun; serialized loaded-address claims alone are insufficient. A multi-LUT mutation test rejects forged keys.
11. **Runtime evidence.** Clock, Rent and EpochSchedule are historical account observations. SlotHashes is historical only with bytes, or materiality-checked by three execution variants. Feature profile, signature/blockhash policy, Instructions construction and provenance are explicit.
12. **Record versioning.** Old JSON still deserializes as V1. New schema-2 records are small manifests; no protocol-specific record variant exists. Corpus and bundle readers dispatch on schema version without rewriting old files.
13. **Fidelity profiles.** Infrastructure selects `HistoricalReplayV1` or `CompleteExecutionV2`. V1 retains its captured outcome/fee/CPI-summary/post-hash policy. V2 compares outcome, fee, logs, grouped CPI indexes/bytes/height, return data, account presence and complete account state. Only an omitted empty return value is normalized.
14. **Semantic boundary.** Evidence resolution and strict baseline fidelity complete before adapter interpretation. A missing adapter does not veto replay; CI reports no semantic coverage. An adapter does not choose fidelity strength.
15. **Targets/dependencies.** Each outer instruction has an explicit role. A target binds program ID and outer index; prerequisites, execution dependencies and standard companions still execute but do not independently produce economic ActionIds. A second target role is rejected for these bounded observations.
16. **Old-record compatibility.** V1 records, bundle bytes and historical fidelity profile are unchanged. V1 execution now calls `LiteSvmBackend` through the same `ExecutionRequest` used by V2.
17. **Stake Pool equality.** Production bundle identity remains `5e5b67ac13e4f6b8249348ad81db29885ee8ee897ba78f6de213b55793f4285f`; `bundle.json` SHA-256 remains `1c41d3c4093778558df3662ff49c11df24a7752b60f95ae61819bb2d335ca2d1`. Verify/baseline/regression/bounded/stale/unevaluable exits remain `0/0/1/1/3/5`, with byte-identical preserved output hashes in [`phase-u4-final-legacy-controls`](examples/phase-u4-final-legacy-controls/controls.json).

The shared CAS is `109,530,773` bytes: `74,265,562` bytes saved, with historical observations and receipt identities retained. 31. **Performance.** On the local debug build, hashing all CAS objects took `9,194` ms. T1/T2 resolution took `15,715/21,444` ms; separate account materialization probes `13,731/19,633` ms; seeding `211/242` ms; default transaction execution `31/47` ms; fidelity and semantic interpretation were below `1/1` ms at the reported resolution. Full three-variant checks took `816/956` ms after resolution. Ordinary CI took `75.37` seconds total. Retained U3F offline two-record replay reported `72.56` seconds; those runs were not a controlled A/B benchmark. A frozen-HEAD CLI and the final CLI ran the same Stake Pool baseline bundle and binary in this workspace: `3.33` versus `3.14` seconds, with byte-identical JSON SHA-256 `7be26a66f3e98f9b96ba6f1270003c158d99968d9ed081c336a97f14782d2099`. These are single-run local timings, not a statistical performance claim. See [`phase-u4-kamino-performance.json`](examples/phase-u4-kamino-performance.json).
32. **Tests.** Full engine suite: 610 passed, zero failed. Hosted server suite: 58 passed, zero failed, one pre-existing ignored. Engine tests include Legacy/V1 controls, native v0, one/multiple LUTs, multi-program dependencies, mixed tokens, evidence and runtime mutations, no-adapter replay, fidelity, corpus and bundle compatibility. Rust formatting passes.
33. **Mutations.** Named assertions reject: forged loaded address, wrong historical boundary, wrong ProgramData deployment, changed CAS content, omitted runtime identity, flattened v0, dropped Scope, second semantic target, semantic promotion before fidelity, raw post-state mismatch, raw tail mismatch, wrong V1/V2 profile, legacy decoding of Token-2022, mutated shared object, missing CAS object, wrong account address, current-state substitution, protocol branch in universal core, no-adapter replay rejection, and a backend limit described as protocol unsupported. See `engine/tests/universal_mutations.rs`, `universal_no_adapter.rs`, and `universal/bundle.rs` tests.
34. **Protocol branches.** Kamino-specific replay-core LOC, evidence-core branches and fidelity-core branches added after the abstractions: **0 / 0 / 0**. Source search found no Kamino- or Stake Pool-ID branch in new universal execution/evidence/fidelity/resolution/bundle code. The local U3F migration wrapper knows its source file layouts. Existing legacy `replay.rs` retains fixture/Memo branches, `historical.rs` retains bounded Memo acquisition, and the old corpus selector contains a Stake Pool label heuristic. These are outside the new replay core and remain explicit limitations.
35. **Provider neutrality.** New evidence stores scheme/host, genesis, exact-slot response context and raw response hash; chunked account observations additionally bind captured request receipts. Resolver never branches on Alchemy. A scan of 318 new corpus files found no API-key, bearer, authorization, password or URL-userinfo pattern; the sole provider scheme/host has no credentials. See [`phase-u4-security-scan.json`](examples/phase-u4-security-scan.json). The existing collector still assumes a provider honoring exact-slot account requests.
36. **Future message format.** A new variant needs compiled-message proof and backend submission plus a frozen validator envelope via `ExecutionInput::validator_transaction_ref`. It need not change CAS, fidelity, corpus, bundle or semantic APIs. New complete-profile legacy records specifically lack this frozen-envelope proof today; old V1 records remain supported under V1.
37. **Future runtime/loader.** A different loader needs binary metadata validation and backend support; a different feature profile needs a capability rule and historical runtime evidence. Neither requires adapter changes. Current capability status distinguishes supported, unsupported backend feature and insufficient evidence.
38. **Justified claims.** The two named production interactions execute through ordinary offline schema-2 corpus, bundle and CI commands; their baseline replay matches U3F and produces semantic coverage. Existing Stake Pool production outputs are unchanged. This is a bounded corpus result, not a representativeness or arbitrary-runtime guarantee.
39. **Remaining limits.** Complete-profile legacy capture is not yet implemented; failed historical transactions need canonical error proof; alternative feature sets/loaders may be unsupported; exact-slot acquisition is not a general collector; the old selector has Stake Pool assumptions; one target per observation is enforced; conservative structural CI can require more semantic mappings for changed candidates. Full account observations retain reconstructable raw responses and returned context but do not bundle the separate request receipt; chunked observations do. The current backend's match on two observations does not establish validator-equivalent behavior in general.
40. **Fourth-protocol readiness.** **A — READY FOR ADVERSARIAL PROTOCOL #4**, as a test of the bounded universal substrate, not a broad support promise. The current core has no protocol-ID branch, and the next protocol can reuse record, evidence, execution, fidelity, corpus, bundle and CI machinery if its historical runtime inputs can be proven.
41. **Recommended adversary.** Orca Whirlpools: it adds Anchor/IDL-heavy instruction structure, argument-conditioned direction, unchecked accounts, concentrated-liquidity state and position math. Drift is a later, stronger internal-accounting adversary. Neither was implemented here.
42. **Adapter Contract v2.** **NEED PROTOCOL #4 FIRST.** Stake Pool and Kamino do not yet show enough repeated adapter friction to justify a new contract, DSL or generator.
43. **Next phase.** Capture one bounded Orca production interaction through the generic historical evidence importer, audit all new runtime/binary requirements, and require full offline fidelity before adding economic interpretation. If a new replay-core branch becomes necessary, revise the universal model before expanding semantic coverage.

The key engineering result is that the modern product path did not need a Kamino replay type, executor, bundle command or CI route. The remaining question for protocol #4 is whether its *historical inputs* and runtime fit this evidence contract, not whether it has a familiar economic adapter.
