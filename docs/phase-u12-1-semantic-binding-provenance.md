These are repository interface claims. The source commit and relevant Git blob IDs are recorded in the binding; no checked build maps this source to the historical ELF.

The frozen transaction independently corroborates the bounded B-to-A interpretation. Verification checks the exact instruction byte shape, direct call, signer and writable roles, token program IDs, and companion writes. It decodes historical token accounts through the shared SPL Token and Token-2022 readers and checks owner program, mint, authority, and initialized state. The retained 653-byte Whirlpool account has the expected account discriminator and the mint A, vault A, mint B, and vault B addresses at the pinned layout offsets; these equal the instruction roles. The retained predecessor and successful historical baseline execution show user B decreased, vault B increased, and vault A decreased. The existing replay proof binds that execution to the historical ELF and checkpoint. Candidate logs and events provide none of these semantic facts.

The four subjects have different immediate proof sources: transaction outcome comes from baseline and candidate execution; `user_input_spent`, `vault_a_tokens_out`, and `vault_b_tokens_in` come from decoded predecessor and final token-account balances. The names and role interpretation still depend on the repository interface. One B-to-A observation does not validate an A-to-B historical execution or other SwapV2 shapes. A controlled opposite-direction shape receives only `repository_source_claim`; unsupported shapes receive `manual_or_unknown`.

## Model and report

`SemanticBinding` has five typed levels: `exact_verified_build`, `standard_program_interface`, `execution_corroborated_external_interface`, `repository_source_claim`, and `manual_or_unknown`. The exact-build level is reserved and fails validation until Eplyx has a source-to-ELF build witness and verifier. Standard-program identity is limited to the recognized System, SPL Token, and Token-2022 program IDs. No such stronger level is claimed for Orca.

For a new schema-2 bundle, the binding is computed from resolved historical inputs and baseline execution, stored with the observation ID in adapter metadata, and included through metadata and manifest hashes in bundle identity. On bundle open, the adapter recomputes the binding from retained evidence and compares it exactly with the stored value. A changed source reference, tier, fact set, ELF hash, or execution hash cannot retain the same bundle identity or pass reconstructed verification. Removing binding metadata from a newly rehashed bundle yields an unclassified legacy-style report with **no semantic assurance claim**. Historical bundles without this field remain readable and serialize their old report shape.

CI JSON places `semantic_binding` beside `replay_proof` and `coverage`; text and Markdown show the tier and exact-build boolean separately. `NamedFinding` severity is unchanged. A consumer of a new report can join a finding's observation ID to its typed binding and cannot equate High or Critical with exact source-to-bytecode verification. An absent field in a historical report means provenance was unclassified under this contract, not exact verified.

## Limits and next work

This is execution corroboration of one interface interpretation, not a reproducible build or proof that the pinned Orca source produced the deployed historical ELF. The pinned Whirlpool byte offsets themselves come from repository source; matching retained state and successful execution corroborate their use in this transaction. The retained final state still cannot measure `user_output_received` after its temporary account closes. Pricing, fees, tick crossings, liquidity, other Orca shapes, and other runtime epochs remain outside coverage. Older bundles have no typed provenance and should be treated as unclassified.

Drift work can begin without carrying this ambiguity forward: it can use the same explicit binding distinction and default to `manual_or_unknown` until its own retained execution and state justify a stronger claim. This phase adds no Drift semantics.
