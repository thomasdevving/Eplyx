# Phase U13 — Drift `settlePnl` production witness

## Result: U13-B, generic closure blocker

A successful, finalized direct `settlePnl` transaction was found and its public block, transaction, account, and pinned interface receipts are retained in [the witness artifact](examples/phase-u13-drift-witness). The offline [audit script](../scripts/analyze-u13-drift-witness.cjs) reconstructs the instruction shape, raw account differences, and complete writable conflict scan. It does **not** create a `ReplayObservationV2`: four later successful transactions write the target's quote SpotMarket, so the archived block-final bytes cannot serve as this target transaction's SpotMarket post-state. The current one-transaction `TransactionClosureProofV1` correctly rejects that validation output. This is a generic transaction-index state-boundary or multi-transaction closure gap, rather than a Drift execution or semantic finding.

No Drift adapter, core branch, observation, corpus, or bundle was added. No baseline execution, offline bundle verification, CI qualification, or replay mutation campaign was run for this witness. There are therefore no observation, corpus, bundle, or matched-replay IDs to report.

## Proof boundary and fidelity

The complete finalized block shows zero earlier transactions declaring any target input writable. It shows four **successful** later transactions declaring the writable quote SpotMarket: indexes 428, 431, 438, and 1245. Their signatures and the complete account list are in `analysis.json`. The archived `getAccountInfo` at slot `409942000` observes the end of the block, after all four. The validator transaction metadata supplies balances, logs, compute units, and token metadata, but no raw SpotMarket state immediately after transaction 73.

`CompleteExecutionV2` is unavailable because direct target transaction-boundary account bytes were not retained. `CheckpointedExecutionV1` contract 2 is the closest existing proof form, but its closure verifier rejects a successful later writer of a validation output. Excluding the known writable, changed SpotMarket from watched outputs would leave the target's market state unvalidated and would not answer U13's full fidelity question. The honest requirement is a trustworthy transaction-index raw state observation or a generic proof that replays and validates the intervening transactions through a multi-transaction closure. The conflict census itself does not supply those bytes.

The available validator envelope supports the expected success, 6,216-lamport fee, 97,801 compute units, logs, empty CPI, and absent token-balance rows. There is no candidate execution against the historical ELF, so none of those fields has a baseline fidelity comparison. The retained User and PerpMarket block-final bytes are usable future outputs; the SpotMarket block-final bytes are only a terminal checkpoint for the wider block. No event or typed decode has been promoted to a substitute for raw-state matching.
